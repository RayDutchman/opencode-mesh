# Mesh 网关级单一 PWA 实施计划

**目标：** 按 [设计规格](../specs/2026-09-30-mesh-pwa-design.md) 恢复 Mesh 网页 PWA：Gateway 自管 manifest 与根 scope Service Worker，接管上游 worker，不引入离线缓存、CacheStorage 清理或请求重放。

**依据：** `docs/superpowers/specs/2026-09-30-mesh-pwa-design.md`。已批准决定见该文 §1；本计划不再逐项请示。

## 全局约束

- 基线分支 `feat/android-apk`，HEAD `bcb5e1d`；`android/` 未提交工作与 `.gitignore`、`docs/maintenance.md` 既有改动完整保留，不清理、不混入、不打 APK。
- 认证不放宽：PWA 路径无凭据均 401，白名单仍只含 `/_mesh/register`、`/_mesh/agent/*`、`/_mesh/deregister/*`。
- SW 脚本不含 `fetch`/`caches`/`importScripts`/`respondWith`；Mesh 代码不写 CacheStorage。
- HTML 改写不得因 manifest 链接缺失而让页面失败；上游入口契约的 fail-closed 仍按既有 `adapt_entry` 处理。
- 设备归属语义不变：请求在 P2P/Relay 选择前固定设备，结果未知的 mutation 失败即失败。
- `docs/maintenance.md` 只追加本轮记录，不覆盖其未提交内容。
- 提交/推送/部署依据当轮授权；提交信息用 Conventional Commits；不引入新依赖。

## 保留边界

网关不可达时冷启动显示浏览器自身离线错误页；Mesh 无离线壳。网关可达但设备不可用时走既有恢复页。此边界需用户明确接受。

## 未验证项（不得当作通过）

- V-1 注入 `crossorigin="use-credentials"` 后 manifest 能否获取；以及当前缺该属性时线上是否真的取不到（写作时无浏览器层观测）。
- V-2 SW 脚本请求能否携带 Basic Auth 凭据；不能则需用户批准后按"单个固定脚本免认证"回退。
- V-3 Chrome 2026 自动安装提示是否仍要求 fetch handler（只影响提示是否自动出现）。
- V-4 旧 worker 是否被及时替换、旧 precache 是否确实不再被使用。
- V-5 PWA 冷启动的最终目标与在途归属（自动化覆盖不等于真机）。
- V-6 真实安装、启动器图标、冷启动、离线冷启动——用户手机验收，验收前不评估是否可移除 Android 客户端。
