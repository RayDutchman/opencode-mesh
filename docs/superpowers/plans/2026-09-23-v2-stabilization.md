**目标：** 修复已审查的上传、取消、WebSocket 和错误响应边界；Gateway 仅为入口，真实 OpenCode 实例均使用明确设备身份；弱网终端行为可追踪。

**授权：** 用户确认认证是误判，关闭该问题；其余按已给出的计划自主实施、验证及部署，独立任务可后台委派。

**架构约束：** 原生多 Server 管理，当前设备 P2P 优先、其他 Server Relay；不重放结果未知的 mutation；不删除数据库或清空用户存储；沿用现有依赖；VPS 本地 OpenCode 通过独立 Agent 注册为普通设备。

## 验收标准

新浏览器只看到明确设备 Server，不出现 Gateway origin 别名；用户改名和外部 Server 保留。VPS 上的 OpenCode 与其他设备使用相同路由，无特殊业务捷径。大上传有界且可取消；终端关闭最终 CLOSED 且不会向新终端输送旧连接数据；首帧前传输错误具有稳定状态、JSON 类型及 reason，已开始的流以错误结束。P2P 失败后后续请求可用 Relay，已发送请求不重放。

## 执行与裁决

- 主 agent 集成，子 agent 限定文件区域与测试职责；避免整体委派和全文件覆盖。
- 认证不再进入修复范围：匿名 8443 HTTP 请求实际为 401，用户确认误判。
- JSON 错误测试先复现 5 项失败；补齐 Content-Type 和首帧前 Response 后通过，并增加非法编码 400 分支的 RED→GREEN 覆盖。
- 集成验证：136 项测试通过；超限上传使用唯一 reader 和前缀块回放，避免 tee 单支取消等待及全量缓存；慢消费者测试证实停止读取源流。
- Ruling: V2.0.6 没有可用的外部启动钩子，集中改写实际产物的唯一 Server getter，并使用独立资源命名空间；未知契约显式失败，升级 OpenCode 时需复验，代价是版本适配维护。
- Ruling: 配置的默认设备探测超时仍保留其稳定身份，不因弱网改绑其他设备；成功确认不是 V2 时拒绝启动，代价是默认设备离线期间其业务请求不可用。
- 弱网记录：同一 PTY 重连带 cursor=318，旧连接关闭后新连接建立；收到的重复 PS1 中有回车和清行而非换行。断网期间创建新 PTY 确实失败，不能宣称终端视觉问题已根治。
- 独立审阅完成，启动发现失败无恢复的回归已通过 RED→GREEN 修复：设备发现 10 秒超时、显示重试提示，每 3 秒重试，同一个 ready Promise 恢复后继续启动。
- Ruling: 离线默认设备的 canonical 身份不改绑，旧项目/书签仍归原设备；首次默认选择可回退到已探测在线的设备，显式用户选择保持。拒绝直接改绑 canonical 的建议，因为会把已有 local 状态归到另一台机器。
- 最后一次弱网视觉采样：初始、resize 及 P2P 断开回 Relay 后的截图均只显示一行提示符；这次未复现用户的两行现象，不作根治声明。
- 低风险延后项：源流单块本身大于限额时暂时持有该块；错误 reason 常量在 Python/JS 两端维护；现有 Gateway 请求体仍全量缓冲。浏览器有界探测不代表端到端流式上传。
