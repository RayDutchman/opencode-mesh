# 同机多 Agent 设计

## 目标与授权

用户批准共享代码与具名 Agent 实例方案，并进一步确认：所有 Agent 共用一份人工配置，身份状态由程序自动维护。保留现有默认实例；每个实例具有独立身份和 systemd 服务。当前本机第二实例名为 `windows`，仅安装准备，保持未启用、未启动，不向 Gateway 注册，等待其 OpenCode 升级 V2。

## 约束

- 复用现有 Python、Shell 与 systemd，不引入运行依赖。
- Agent 连接上游，不监听上游端口。
- 默认实例现有配置、设备身份和服务路径保持兼容。
- 具名实例名称只允许安全的 ASCII 字母、数字、连字符和下划线，拒绝空值、路径分隔符及 systemd 转义输入。
- 同一安装目录共享源码、虚拟环境和 `config/agents.json`；顶层为公共配置，`agents` 映射按实例名配置上游及显示名。实例字段覆盖公共字段，原对象不得被修改。
- 统一配置禁止指定 `state_file`；程序派生内部路径：默认实例 `data/agent-state.json`，具名实例 `data/agent-state-<instance>.json`，以配置文件所在目录的父目录为安装根目录。身份只保存到这些文件，不写回人工配置。
- 旧的单 Agent 配置在未指定实例时继续兼容。旧配置迁移必须保留原身份，其他实例不得复制其 agent_token/device_id。
- `device_name` 配置用于注册显示名，缺省使用 hostname；名称不是身份。
- 不修改 OpenCode 配置、数据库、现有端口转发或认证策略。
- 公开文档和测试使用虚构地址；实际部署配置保持在忽略文件中。

## 生命周期

安装、部署、卸载入口统一支持可选实例名。默认 Agent 继续使用 `opencode-mesh-agent.service`；具名实例使用 `opencode-mesh-agent@<instance>.service`。Gateway 不接受 Agent 实例参数。

安装提供显式的仅安装模式：写配置和 unit，执行 daemon-reload，不 enable/start/restart。重复安装不得重置身份，或把仅安装误变成开机自启。

共享源码升级是整个安装目录的操作。升级前记录该目录关联服务的运行状态；仅重启升级前运行的服务，停止状态的实例保持停止。失败回滚恢复共享代码和原运行状态，不回滚或重置身份文件。不得对其他安装目录或 OpenCode 服务进行操作。

卸载具名实例仅处理该实例服务及共享配置对应的实例键；默认保留自动身份状态、共享源码和其他实例。完整删除安装目录须明确识别其他已配置或已安装实例（包括 inactive）并拒绝破坏性清理。

## 验证

回归验证覆盖默认参数兼容、非法实例名、独立配置与身份、仅安装不启用、显示名回退、共享升级的运行状态保持和单实例卸载隔离。优先以临时目录、模拟 systemctl/远端命令验证脚本，不用生产服务做失败注入。

最终运行全套测试与 Shell/Python 语法检查。本机验收确认现有 Agent 仍 active 且身份未变，新增实例配置目标正确、inactive 且 disabled，没有新注册记录。Windows V1 不计入 V2 功能验收。
